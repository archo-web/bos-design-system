1. List Page

가장 자주 쓰는 패턴. 항목들의 목록을 보여주고, 검색/필터/정렬/추가가 가능한 화면. (멤버 목록, 프로젝트 목록, 주문 목록 등)

Header Title + Primary Action
Toolbar Search · Filter · Sort · View Toggle
Content (Table or Card Grid)
Footer Pagination · per-page
패턴 구조 — Header / Toolbar / Content / Footer

사용된 컴포넌트

Tables Input field (검색) Dropdown menu (필터/정렬) Button group (뷰 전환) Pagination Button (Primary CTA)
실제 예시 — 멤버 관리 페이지 v4 (5가지 상태 + 다크 모드 토글 포함). member-management-v4.html 참조.

2. Master-Detail NEW 2026-05-08

좌측 리스트 + 우측 상세를 한 화면에. 리스트 ↔ 상세 왕복이 잦은 작업에 적합 (이메일·메시지·코드 리뷰).

항목 1
▶ 항목 2
항목 3
항목 4
항목 5
좌 360px 리스트 + 우 1fr 상세. 선택된 항목은 bg-brand-softer.
Dropdown list item (좌측) Pagination Card (우측 상세) Breadcrumbs
모바일 대응 — 모바일에서는 단일 화면 전환식으로 (리스트 → 상세 클릭 → 상세만 표시 → 뒤로가기로 리스트 복귀). 그대로 두면 폭이 좁아 사용 불가.

3. Card Grid NEW 2026-05-08

시각적 항목(상품·이미지·프로젝트)을 카드로 펼치기. 텍스트보다 이미지/시각 요소가 핵심일 때.

CSS Grid repeat(auto-fill, minmax(280px, 1fr)) + gap spacing-4.
Card (With Image / E-commerce / Pricing card) Input field (검색) Dropdown menu (정렬) Pagination 또는 Load more
List Page와의 차이 — 정보 밀도가 낮고 시각 요소가 결정적이면 Card Grid, 빠른 스캔과 정렬·필터가 핵심이면 List Page.

4. Detail Page

하나의 항목을 깊이 보여주는 화면. 정보 + 관련 액션 + 하위 데이터. (멤버 프로필, 주문 상세, 문서 보기 등)

Header Breadcrumbs · Title · Edit/Delete · Status
Main Content (정보 섹션들)
Sidebar 320px
데스크톱: Main + Sidebar 좌우. 모바일: 세로 스택

사용된 컴포넌트

Breadcrumbs Nav Tabs (선택) Card Badge (상태) Button (Edit/Delete/More)

5. Modal Form / 6. Page Form

데이터를 입력/수정. 5개 필드 이하면 Modal Form, 6개 이상이면 Page Form.

Title
Section 1 — 기본 정보 (Label + Input × N)
Section 2 — 추가 정보
Section 3 — 옵션
취소 · Primary CTA
필드 사이 20px, 섹션 사이 32px. 폼 최대 폭 640px (가독성)

사용된 컴포넌트

Forms (Input/Select/Search/Number/...) Label Helper Checkbox & radio Toggle Modals (간단한 폼)

7. Wizard / Stepper NEW 2026-05-08

긴 폼을 여러 단계로 나눠 진행. 각 단계는 단일 책임 + 진행 상황 표시. 회원가입·결제·워크스페이스 만들기에 적합.

단계 진행 (●━━━○──○──○) + 단계별 폼 + Back/Next. 단계 4개 이상이면 컴팩트 stepper 사용.
Stepper (35 variants) Forms Button (Back / Next / Save & Exit) Progress Bars (선택)
단계 수 가이드 — 3~5단계가 이상적. 6단계 이상이면 사용자 이탈률 급증. 마지막 단계는 항상 검토(Review) 단계로.

카테고리별 환경설정. 즉시 반영(Toggle)과 저장 후 반영(Form)을 시각적으로 분리하는 게 핵심.

Nav Tabs (Vertical) 또는 Sidebar Toggle (즉시 반영) Forms (저장 후 반영) Button (Save)

11. Onboarding NEW 2026-05-08

첫 진입 사용자에게 핵심 기능 안내. 3단계 이내 권장. 반드시 Skip 가능.

일러스트 + 헤딩 + 설명 + 단계 표시 + Skip/Next. Auth Page와 유사한 중앙 정렬 레이아웃.
Modal (전체 화면) Stepper (단계 표시) Button (Skip / Next) Card (Empty state 변형)
변형 — Tooltip 투어(실제 UI 위에 단계별 Tooltip), Empty State 가이드(빈 화면에 첫 액션 CTA), Checklist(장기 온보딩)도 가능.

12. Empty / 404 / Error NEW 2026-05-08

데이터 없음·페이지 없음·오류. 좋은 디자인 시스템의 기준은 이 패턴이 얼마나 잘 정의되어 있느냐입니다.

404 Error Page (Figma 공식 디자인)

좌측 큰 비주얼(404) + 우측 콘텐츠(헤딩·설명·원인 카드·CTA 2개) 구성. 가로 분할 레이아웃은 데스크톱 우선, 모바일에선 세로 스택.

기본 Empty 상태 (단순 변형)

404처럼 큰 화면이 아닌, List/Card Grid 안의 빈 데이터 영역에 들어가는 가벼운 형태.

아이콘 + 헤딩 + 설명 1~2줄 + Primary CTA + Secondary. List Page/Card Grid의 빈 영역에 그대로 사용.

4가지 변형 비교

변형 핵심 메시지 발생 가능한 원인 안내 CTA

500"잠시 문제가 발생했습니다"일시 장애 / 재시도 권장다시 시도, 새로고침, 고객지원
Card (원인 안내 박스) Button (Primary + Secondary) Icon shape (404 큰 비주얼) Badge (ERROR 코드)
"발생 가능한 원인" 카드의 가치 — 단순 사과형 메시지("페이지가 없습니다") 대신 사용자가 다음 행동을 추정할 수 있는 구체적 힌트 제공. 404/500에 특히 효과적.
Empty 상태가 적용되어야 할 곳 — 모든 List Page · Card Grid · Master-Detail (선택 안 됨) · 검색 결과 없음 · 알림/Activity feed · Inbox. 빈 흰 화면으로 끝나면 안 됨.

패턴 선택 의사결정 트리 (다면적)

3가지 관점으로 같은 결정을 검증합니다. 한 관점만 보고 결정하지 말고, 적어도 두 관점이 같은 패턴을 가리키는지 확인하세요.

Step 1 — 액션 동사 (사용자가 "무엇을 하려는가")

사용자가 이 화면에서 하려는 동사는? ├─ 본다 / 찾는다 (조회·탐색) │ ├─ 동일 형태 여러 개 → 1·2·3 (List / Master-Detail / Card Grid) │ ├─ 한 항목 깊이 → 4 (Detail Page) │ └─ 여러 지표 동시 → 8 (Dashboard) │ ├─ 한다 / 보낸다 (입력·실행) │ ├─ 짧은 폼 (≤5필드) → 5 (Modal Form) │ ├─ 긴 폼 (≥6필드) → 6 (Page Form) │ └─ 단계적 흐름 → 7 (Wizard) │ ├─ 바꾼다 (설정 변경) → 9 (Settings) │ ├─ 진입한다 (인증·온보딩) │ ├─ 로그인/가입 → 10 (Auth) │ └─ 첫 사용 안내 → 11 (Onboarding) │ └─ 오류·없음을 만났다 → 12 (Empty / 404 / Error)

Step 2 — 정보 구조 (데이터/콘텐츠 모양)

이 화면에 담을 콘텐츠의 모양은? ├─ 같은 스키마 행 여러 개 (테이블형) │ ├─ 빠른 스캔 + 행 클릭 → 1 (List Page) │ └─ 행 클릭 시 우측에 상세 → 2 (Master-Detail) │ ├─ 같은 스키마 카드 여러 개 (시각적) │ → 3 (Card Grid) │ ├─ 단일 항목, 다층 정보 │ → 4 (Detail Page) │ ├─ 단일 폼 (필드 모음) │ ├─ 짧음 (≤5필드) → 5 (Modal Form) │ ├─ 김 (≥6필드) → 6 (Page Form) │ └─ 단계 분리 가능 / 필요 → 7 (Wizard) │ ├─ 여러 차원 동시 비교 │ → 8 (Dashboard) │ ├─ 카테고리별 옵션 묶음 │ → 9 (Settings) │ └─ 단일 카드/컨테이너 중앙 정렬 ├─ 인증 → 10 (Auth) ├─ 환영/안내 → 11 (Onboarding) └─ 빈 상태/오류 → 12 (Empty/404/Error)

Step 3 — 마이크로 분기 (규모·빈도·맥락)

같은 1단계, 2단계 결과라도 세부 조건에 따라 패턴을 미세 조정합니다.
